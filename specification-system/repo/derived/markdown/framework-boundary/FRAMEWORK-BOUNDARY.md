## Decision_basis

- **Framework_source_and_template_identity:**
  - **decision:** framework-source-and-distributable-template-are-distinct
  - **rationale:** The framework source repository includes development tooling, tests, and construction artifacts that are not part of the distributable template. The template is a derived subset.
- **Artifact_copy_semantics:**
  - **decision:** template-copies-framework-generic-artifacts-and-derives-instance-local-starting-artifacts
  - **rationale:** Template initialization copies framework-generic validation entry points, generic schemas, and level template structure; generates initial product overview and implementation-plan stubs and initial level roots; selects hosting-platform, language, and build profiles; and omits framework-source construction artifacts, framework tests, framework development tooling, and framework governance records.
- **Template_initialization:**
  - **decision:** initialized-product-repositories-derive-from-the-framework-template
  - **rationale:** Initialized product repository creation uses explicit inputs, outputs, copy semantics, and standalone validation capability. The initialized repository preserves framework provenance and selected profiles, keeps product-specific content separate from framework authority, and does not depend on maintained framework source.
- **Template_provenance_preserved:**
  - **decision:** provenance-is-preserved
  - **rationale:** Every initialized repository must be able to identify the framework revision from which it was created to support audit, update, and separation workflows.
- **Framework_update_consumption:**
  - **decision:** product-repositories-may-consume-framework-updates
  - **rationale:** An initialized product repository may receive framework improvements through explicit governed update operations. The product repository retains authority over its product-specific content and may accept or defer framework updates through its own governed process.
- **Product_profile_selection:**
  - **decision:** profiles-are-selected-during-initialization
  - **rationale:** Hosting-platform, language, and build profiles are selected when a product repository is initialized from the template. Profile selection is recorded in template provenance.
- **Authority_separation_principle:**
  - **decision:** framework-authority-and-product-authority-remain-separate
  - **rationale:** Framework authority controls framework source, template definition, and template revisions. Product authority controls product overview, plan, specifications, artifacts, and local customizations. Neither may silently override the other. Product specifications must be explicitly accepted under product authority; framework revisions must be explicitly accepted under framework authority.
