## Summary

This Stage 2 specialization defines the exact authoritative no-op result envelope, fatal pre-result failure envelope, status vocabularies, identity relationships, diagnostic shape and stable codes, failure stages, effect-state representation, terminal classes, process exit codes, and stdout/stderr behavior. It consumes the accepted Stage 2 common payload contract without redefining it.

## Definitions

### Stage 2 authoritative result (`L2-S2RC-AUTHORITATIVE-RESULT`)

The single closed JSON result envelope emitted after the core can establish a request identity, workflow identity, result identity, and the complete set of operation identities required to represent the terminal condition truthfully.

### Stage 2 fatal pre-result failure (`L2-S2RC-FATAL-PRE-RESULT-FAILURE`)

The closed JSON failure envelope emitted only when UTF-8 decoding, JSON parsing, or result construction prevents the core from constructing a truthful authoritative result identity and envelope.

### Stage 2 terminal class (`L2-S2RC-TERMINAL-CLASS`)

One of exactly four deterministic process outcomes: success, invalid-input-result, processing-failure-result, or fatal-no-result.

### Stage 2 diagnostic (`L2-S2RC-DIAGNOSTIC`)

A closed machine-consumable diagnostic object identified by diagnostic_id and stable code, with an exact failure stage, scope, optional identity references, and explanatory message text that is never the sole discriminator.

### Stage 2 failure stage (`L2-S2RC-FAILURE-STAGE`)

One exact stage from utf8-decoding, json-parsing, payload-validation, identity-validation, no-op-disposition, or result-construction.

### Stage 2 no-op disposition (`L2-S2RC-NO-OP-DISPOSITION`)

The successful Stage 2 lifecycle outcome in which processing succeeds, workflow status is no-op-completed, every operation status is no-op, no effect is requested, and execution remains unattempted.

### Stage 2 effect-state object (`L2-S2RC-EFFECT-STATE`)

The closed object containing request, authorization, execution, observation, and verification dimensions using the exact values inherited from GVE Level 3 Evidence and Result Realization.

### Stage 2 process boundary (`L2-S2RC-PROCESS-BOUNDARY`)

The deterministic mapping from terminal class to authoritative-result availability, exit code, stdout content class, and stderr content class.

References: `L2-S2RC-AUTHORITATIVE-RESULT`

### L2-S2RC-REQ-004

### L2-S2RC-REQ-006

For the accepted no-op lifecycle, request is not-requested, execution is unattempted, observation is unobserved, and verification is unverified at workflow and operation scope. No-op status establishes no requested, authorized, attempted, completed, observed, or verified effect.

References: `L2-S2RC-NO-OP-DISPOSITION`, `L2-S2RC-EFFECT-STATE`

### L2-S2RC-REQ-007

References: `L2-S2RC-EFFECT-STATE`

### L2-S2RC-REQ-008

References: `L2-S2RC-AUTHORITATIVE-RESULT`, `L2-S2RC-DIAGNOSTIC`

### L2-S2RC-REQ-009
